# Проект: Свадьба 3

Одностраничный сайт иммерсивного ужина **7 ноября 2026** для пар, планирующих свадьбу в 2027 году.
Единственная конверсия — заявка на участие. Оплаты на сайте нет: организатор связывается с парой сам.

Стек: Vite + React + TypeScript, серверная функция Vercel `api/lead.ts`, тесты на Vitest.
Оформление — по бренд-брифу «Проект: Свадьба 3» (палитра, Cormorant / Great Vibes / Manrope, рамка-билет).

## Запуск

```bash
npm install
npm run dev        # сайт + локальный /api/lead
npm test           # тесты
npm run build      # проверка типов и сборка в dist/
```

Копия `.env.example` → `.env.local` для локальных переменных.

## Где править контент

Все тексты и факты лежат отдельно от компонентов:

| Файл | Что внутри |
|---|---|
| `src/content/event.ts` | Дата, город, площадка, время, цена, состав участия, организатор, контакты, логотип, статус правил розыгрыша, версия политики. `null` = «уточняется» |
| `src/content/sections.ts` | Тексты блоков 01–07, CTA, подписи формы, сообщения об успехе и ошибке |
| `src/content/vendors.ts` | Массив подрядчиков (`id, name, specialty, photo, shortBio?, profileUrl?, order, isPublished`) |
| `src/content/faq.ts` | FAQ (вопрос публикуется, когда есть ответ и `isPublished: true`) |

Выдуманных данных в коде нет. Что не подтверждено, показывается как «уточняется» или скрыто.

## Приём заявок

`POST /api/lead` (`server/lead-handler.ts`): проверяет и очищает ввод, ставит лимит частоты, отбрасывает ботов (скрытое поле), не создаёт дубль при повторе с тем же `clientRequestId`, доставляет заявку в подключённые каналы. Успех возвращается только после того, как сработал хотя бы один канал.

Каналы включаются переменными окружения (секреты хранятся только на сервере, см. `.env.example`):

- `LEAD_WEBHOOK_URL` (+ `LEAD_WEBHOOK_SECRET`): JSON с заявкой уходит на ваш URL (Google Apps Script, Make, n8n, CRM).
- `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID`: уведомление организатору.

Без каналов `/api/lead` отвечает 503, а форма показывает ошибку, а не «отправлено».
Новый канал: реализуйте `LeadSink` (`server/types.ts`) и добавьте в `server/providers/index.ts`.

Фиксируется: `createdAt`, UTM-метки, страница отправки, согласие с версией политики, статус доставки по каждому каналу (в лог, без персональных данных).

**Ограничение:** лимит частоты и защита от дублей живут в памяти функции. На Vercel это best-effort: работает в пределах одного «тёплого» инстанса. Для строгой гарантии подключите хранилище (Upstash/Redis, БД).

## Публикация (Vercel)

1. Импортируйте репозиторий в Vercel (фреймворк Vite определится сам, `vercel.json` уже есть).
2. В Settings → Environment Variables задайте переменные канала доставки.
3. `VITE_PREVIEW_PLACEHOLDERS` на публичном сайте **не включайте**.

## Тестовая сборка и заглушки

`npm run dev` и сборка с `VITE_PREVIEW_PLACEHOLDERS=true` показывают технические заглушки: карточки подрядчиков, FAQ и анонс розыгрыша. На публичном сайте они скрыты, пока нет реальных данных и утверждённых правил розыгрыша (`event.raffle.rulesApproved`).

## Аналитика

События готовы в `src/lib/analytics.ts`: `page_view`, `cta_click` (с блоком), `application_start`, `application_submit_success`, `application_submit_error`, `vendors_scroll`, `raffle_rules_open`. Провайдер не подключён: после выбора и учёта согласия на cookie вызовите `setAnalyticsSink(fn)`.

## Логотип и фото

Логотип — готовый файл: положите его в `public/` и укажите путь в `event.logo`. Фотографий зала (бархат, занавес, лампы) пока нет: фон секций плоский, на первом экране мягкое пятно света.

## Что нужно решить до запуска

1. Город, площадка, время начала и окончания.
2. Стоимость и формат участия (на одного или пару, что включено).
3. Куда отправлять заявки: webhook/CRM/таблица/Telegram-бот и токены.
4. Реальные подрядчики: фото, имена, специализации, ссылки.
5. Название и реквизиты организатора, реальные контакты.
6. Правила розыгрыша главного приза и условия сертификатов. До утверждения анонс приза скрыт.
7. Политика обработки персональных данных и её версия; условия участия (страницы `/privacy`, `/terms`, `/raffle-rules` помечены «ДОКУМЕНТ НЕ УТВЕРЖДЁН»).
8. Планируются ли рекламные рассылки (если да, включите `marketingConsentEnabled`).
9. Ответы для FAQ.
10. Формат и сроки передачи фотографий с вечера.
11. Файл логотипа и фотографии для оформления.
12. Нужен ли строгий лимит частоты (общее хранилище).

## GitHub Pages
Сайт публикуется на `la-fete.ru` через GitHub Pages, заявки принимает Google Apps Script. Подробно: [docs/GITHUB_PAGES.md](docs/GITHUB_PAGES.md).
В сборке адрес приёма задаётся `VITE_LEAD_ENDPOINT` (в Actions это переменная `LEAD_ENDPOINT`); без него форма использует `/api/lead` (Vercel).
